# EIP-8141 frame transaction — the EF alt-mempool artifact

This is the Ethereum Foundation track artifact. It is **not** a bridge and it is **not** Arc
settlement: it runs on the Alternative Mempool devnet (chain `1337`) against a separate reference
vault. The Arc deployment is the product.

## Why a frame transaction here, and not an ERC-4337 `UserOperation`

The alt-mempool track asks for something the public mempool cannot admit. Ours is the second bullet
in the track description: *"more flexible state access in sender or paymaster"*.

In 4337 the paymaster's `validatePaymasterUserOp` is a separate call with its own restricted context,
and sponsorship is a bundler's business: the bundler must hold a deposit for you, and if it stops
serving you, your user cannot be paid. EIP-8141 lets the **account's own code** decide what is valid,
frame by frame, so the payment authorisation is a frame of the same transaction that performs the
release. No bundler, no deposit, no EntryPoint:

```
frame 0  VERIFY  scope=EXECUTION_AND_PAYMENT   budget  30 000   ── who is allowed to run this tx
frame 1  VERIFY  scope=PAYMENT  target=paymaster budget  50 000 ── PAYMENT frame: this address pays the fee
frame 2  SENDER  target=BountyVault  state=1 000 000           ── releaseBounty(dealId, 0, whitehat)
```

The researcher is `whitehat` in frame 2's call data. They sign nothing, hold nothing, and their
address never appears as `tx.sender` — they are a beneficiary, not a participant in the fee market.

## What actually happens, end to end

`POST /api/claim` (and `npx tsx scripts/claim.ts`) do the same six steps:

1. Read the devnet deal from `BountyVault` (`getDeal`) and refuse unless it is `Open`.
2. Run the **Arkiv guard**: a live, unexpired anchor scoped to `chainId = 1337` whose
   `whitehatWallet`, `protocolWallet` and `amount` match the chain. No anchor → `403`, and no frame
   transaction is built.
3. Refuse if the devnet is not producing blocks (head older than 10 minutes → `503`), so a frozen
   devnet does not look like our bug.
4. Build the frame transaction with `@forshtat/hegota-support` (`profile: ethrex-eip8141-tracer`),
   `chainId 1337`, three frames as above.
5. `eth_sendFrameTransaction` to `https://altmempool.forshtat.com/rpc`.
6. Poll `eth_getTransactionReceipt` up to 180 s and return the per-frame statuses to the UI.

The relayer key (`PROTOCOL_PRIVATE_KEY`) is server-only and is the `sender` of the frame transaction;
it is also the protocol account the vault already knows. Sponsorship here means "the protocol account
pays", not "a paymaster contract was debited" — stated plainly because it is what the code does.

## The trade-offs we accepted

- **The relayer is a liveness dependency.** If it stops, the devnet demo stops. There is no
  permissionless path to news a sponsored release, which is fine for a research artifact and not
  fine for a product.
- **It is chain-1337 only.** Frame transactions are not deployable on Arc today; the Arc product uses
  a plain EOA call plus (deployed, unused) 4337 paymaster wiring.
- **Rate limited to 5 claims/minute per IP**, because the route spends a funded relayer key.
- **The devnet is shared infrastructure** and has stalled for hours during the event. The UI and the
  API both say so rather than timing out silently.

## Redeploying after a devnet reset

The devnet is shared and gets reset during the event. On the reset we saw, the head dropped from
`#408262` to `#1856`, which leaves the recorded contracts with no code at all. Rerun the deploy
inside Arc Studio (all deployments go through Studio, never from a local copy of `contracts/`):

```
# in the Arc Studio sandbox
forge script contracts/script/DeployDevnet.s.sol:DeployDevnet \
  --rpc-url https://altmempool.forshtat.com/rpc --broadcast --legacy --slow \
  --gas-estimate-multiplier 800 --private-key $PROTOCOL_PRIVATE_KEY
```

Two things that cost us an afternoon, both now baked into the command above:

- **`--gas-estimate-multiplier 800` is mandatory.** The devnet prices contract creation at roughly
  5× Foundry's local EVM schedule. With Foundry's own limit the three creations consume their entire
  gas allowance and revert with `status 0x0` while `gasUsed == gasLimit` — which reads like a
  constructor revert and is not one. Devnet `eth_estimateGas` for the same creations: 3 051 173
  (mUSDC), 2 556 776 (paymaster), 5 386 766 (vault).
- **`--slow`** sends one transaction at a time, so a failure does not leave a half-deployed stack.

The script deploys mUSDC, funds and deploys `SponsorPaymaster` (50 ETH via its payable constructor —
a plain transfer would hit the `fallback` and fail), deploys the vault, mints test USDC to the
relayer and opens deal #0. Afterwards update `frontend/src/lib/constants.ts`
(`DEVNET_VAULT_ADDRESS`, `DEVNET_PAYMASTER_ADDRESS`), `frontend/.env.local`, `deployments.json` and
the reference transactions below.
